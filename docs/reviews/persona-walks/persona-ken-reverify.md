## UC2：中午 12:30 記一筆 88 元早餐（現金）

**步驟（實際點擊路徑）**
1. 首頁右上點「＋ 快速記帳」pill → dialog 開。
2. **在還沒碰任何付款方式之前**，先量測「現金 / 刷卡 / 轉帳」三顆 pill 的 highlight 狀態，並讀「扣款帳戶」欄顯示哪個帳戶。
3. 項目名稱填 `早餐 #63121`、金額填 `88`（type 預設就在「支出」）。
4. 點「新增交易」→ dialog 關閉 + toast「已新增交易」。

**觀察到的**
- [PASS] dialog 一開，付款方式那排**不是全灰**：`轉帳` pill 已 highlight（`aria-checked=true`），`現金`/`刷卡` 灰。扣款帳戶欄同步顯示「個人零用」。→ 付款方式 pill 與預設扣款帳戶**確實一開就對齊**，我不用為了讓它「對上」多點一次。**K-A2.1（帳戶顯示 A、pill 卻亮 B）已修復。**
- [MEDIUM] 但預設落在**「個人零用」（銀行帳戶）＋「轉帳」**，而我這筆是**付現金**。要如實記錄，我得手動把 pill 切成「現金」（帳戶跟著跳到「隨身現金」）。
- [PASS] 填單→送出→dialog 關閉→toast 一氣呵成，全程 < 15 秒沒有卡頓。

**Persona 的內心 OS**
> 開起來那排付款方式有一顆是亮的，帳戶欄寫「個人零用」，轉帳那顆也亮著——OK 至少它們是一致的，不會再出現「帳戶寫現金、現金卻是灰的要我再戳一下」那種鬼打牆，這是我上次抱怨的點，這次對了。
>

**Anomalies**
- **A2.1 · MEDIUM · 現金消費情境下，快速記帳預設落在銀行帳戶（個人零用）＋轉帳，而非現金錢包**
  - repro：首頁 → 快速記帳 → 觀察付款方式（轉帳亮）＋扣款帳戶（個人零用）。對一個現金為主的記帳者，每筆現金支出都要手動改一次。
  - 影響：Ken 每日高頻現金記帳，每筆多一次切換 → 累積摩擦，直接抵觸他「15 秒一筆」的核心目標。
  - 性質澄清：這是**預設帳戶選擇 / 記憶策略**問題，**不是** pill–帳戶 sync bug（sync 已驗證正確）。
  - suggested fix：`src/components/dashboard/quick-add-transaction.tsx:104,146` — `useState(accounts[0]?.id)` / `resetForm()` 的預設 accountId。可考慮：(a) 記住上次成功送出的 accountId（localStorage / profile 設定）；或 (b) 提供「預設扣款帳戶」使用者設定；或 (c) 依帳戶用途挑更適合現金族的預設。

## Cross-Module Integration Verdict

跨模組一致性是 Ken 最在意的信任基礎（他明講受不了「手機 vs 網頁不一致」「介面成功資料對不上」）。本輪三條整合鏈**全部為真、非表面戲法**：

1. **快速記帳寫入 ↔ /transactions 讀取** ✓
   首頁 dialog 建立的 `早餐 #63121 −$88 / 個人零用 / 2026-07-03`，在 `/transactions` 以完全相同的金額、帳戶、日期出現；同筆也即時反映在首頁「個人」板塊卡的本月明細。寫一處、三處（板塊卡 / 明細列 / 分析）同步——`revalidatePath` 鏈有效。

2. **分類 ↔ 分類系統** ✓（本輪最關鍵）
   網頁打字「早餐」→ server `classifyByKeyword` → `food_dining` → 在**明細列 badge**、**板塊卡明細**、**編輯 dialog 花費類型下拉**三個地方都顯示「餐飲食品」，且與 LINE bot 端行為對齊。Ken 最怕的「網頁記帳比 LINE 笨、全落其他」已不復存在。

3. **編輯 project_tag ↔ 列表可見** ✓
   編輯 dialog 存「太太醫療」→ `router.refresh` → 該列即時長出 🏷️ chip，無需重開 dialog 驗證。標籤唯一性驗證（本輪用 `早餐 #63121` 精準鎖定 MY 列）確認 chip 是掛在**我剛改的那筆**，不是被舊資料的同名 tag 蒙混通過。

> 整合裁決：**無「看起來有資料、卻對不上」的假整合**。四個舊 anomaly（K-A1.1 / A2.1 / A3.1 / A4.1）在真實點擊路徑層級皆已修復。
